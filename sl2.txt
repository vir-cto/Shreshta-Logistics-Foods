1. WHAT THIS PROJECT IS
==================================================
One Next.js 14 (App Router + TypeScript + Tailwind + Firebase) platform with two modules:

A. Sreshta Logistics  – full operational logistics system (Xpression-style)
B. Sreshta Foods      – e-commerce (pickles, snacks, weight variants) + Cashfree payments

Public site has a Swiggy-style dual-tab switcher (Logistics ↔ Food).
Admin is under /admin with role-based access (Super Admin, Co-loaders, etc.).

Reference sites the client wants to match:
- Public logistics look & feel → https://giantwings.in/
- Admin operational UX → https://xpresion.sssxpress.in/  (especially the AWB Entry / Booking page)

   - Charge Details (Contract Charges, Other Charges, Surcharge, IGST/CGST/SGST, Total)
   - Bottom Save / Cancel + AWB UserID, POD UserID, Manifest No, Invoice No

   - hsCode / HSN Code per line item
   - shopName + shopAddress per line item (as in sample Proforma)
   - csbType (CSB4)
   - exportReason (UNSOLICITED GIFT - NOT FOR SALE, SALE, SAMPLE, GIFT, etc.)
   - termOfInvoice (CIF, CFR, FOB, EXW, DAP, DDP, etc.)
   - documentType + documentNo (GSTIN, etc.)
   - preCarriageBy (FDX, DHL, etc.)
   - accountCode / hubCode (WH439 / WF439 style) – must appear on every document
   - volumetric weight calculation already exists in calculations.ts – just wire it properly

C. PDF Generation (must match samples exactly)
   - No real AWB Label generator yet (needs barcode, POD signature box, piece dims, charged weight, ICL-style layout)
   - No Proforma Invoice generator yet (needs item table with HS codes + shop details, amount-in-words “INR Three Thousand Two Hundred Only”, CSB4 stamp, dual logo support)
   - Current src/lib/pdfGenerator.ts is a generic invoice only → must be replaced/extended
   - PDFs must be generated on-the-fly in memory (no storage of PDFs required)
   - Logistics invoices use Logistics logo + account code
   - Food invoices use Food logo + company as auto-sender

D. Dynamic Tracking Stages
   - Current TRACKING_STATUSES are hard-coded
   - Super Admin must be able to add / edit / delete / reorder stages
   - Stages apply to both Logistics AWBs and Food orders
   - Tracking matrix page must show every AWB in rows with checkboxes for each stage
   - Checking a box updates the public tracking timeline instantly

E. Fuel Surcharges + Co-loaders
   - Super Admin only can add/edit/delete fuel surcharge rows (Name e.g. DHL/FedEx + cost)
   - Co-loaders can only view/apply them
   - Co-loader management: create logins + assign account codes (like WF439)
   - Account code must appear on AWB labels and Proformas

F. Other
   - WhatsApp: prefer side-drawer + Cloud API; fallback to wa.me link is acceptable
   - Day-End page: three buttons (Warehouse Pending / Delivery Pending / Booking Pending) + date filter + Excel/PDF export
   - Masters (Senders, Receivers, Customers, Service Centers, Destinations, Vendors, Services) need full CRUD + Excel/PDF export
   - Dashboard must look like Xpression (Outbound/Inbound pie charts that are clickable filters)
   - ModuleSwitcher (Logistics ↔ Food) already exists but must drive sidebar + header context
